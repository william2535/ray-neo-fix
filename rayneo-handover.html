01

It works today

On the handheld, right now:

termux-usb -r -e "python -u rayneo_head.py --mode mouse --sens 25" \
  /dev/bus/usb/001/002

Head motion drives the system cursor. Two seconds of calibration at startup, then live. Keys while running: m mouse, s screen, r recentre, c recalibrate, q quit.

Shortcuts exist at ~/.shortcuts/ and the launcher auto-detects the USB path, so replugging does not break them. The only unfinished bit on Android is getting an icon onto the Cocoon home screen — Cocoon appears not to accept Termux widgets.

Before the APK, try this: long-press the Termux:Widget icon in the app drawer. Shortcuts and widgets are different Android mechanisms, and Cocoon may allow one but not the other.

Do not re-derive any of this. All measured, all verified.

The trap that cost the most time: floats start at offset 4, not 8. Reading from 8 still looks like gravity when the glasses lie flat, because accel X is near zero there. It only falls apart on the left side.

04

On the PC: the APK

This is the next real step, and it needs a desktop.

What to install

  • Android Studio — free, developer.android.com/studio. Large download, ~1 hour with the SDK.
  • No phone connection needed to build. You produce an APK and copy it across.

What the app has to do

  1. USB permission — UsbManager, request access to VID 0x1BBB / PID 0xAF50. An intent filter can auto-launch when the glasses are plugged in.
  2. Claim the interface — openDevice(), then claimInterface(intf, true). The true force-detaches the kernel HID driver. This is what Termux does under the hood.
  3. Send the enable — controlTransfer(0x21, 0x09, 0x0301, 0, byteArrayOf(0x00, 0x01), 2, 600)
  4. Poll — bulkTransfer on endpoint 0x81, 64 bytes, in a background thread.
  5. Decode — ByteBuffer.order(LITTLE_ENDIAN).getFloat(4) and on in fours.
  6. Port the tracker — the Tracker class in rayneo_head.py translates to Kotlin almost line for line. Keep the sub-pixel carry.
  7. Output — uinput from Kotlin needs NDK/JNI. Simplest first version: keep the Python mouse and have the app talk to it, or ship screen mode only and add mouse later.
Suggested order. Get a screen showing live pitch/yaw/roll numbers first. That proves USB, decode and tracker all work inside a real app. The UI and the mouse output come after.

What the UI needs

  • Mouse / screen toggle
  • Sensitivity slider, 5 to 50
  • Recentre and recalibrate buttons
  • Invert X and invert Y switches
  • A live readout, useful for confirming it is alive
05

Other things worth doing

  • Publish it. GitHub, your name, MIT or Apache-2.0 licence. A dated public repository is what establishes you did this first.
  • Confirm the yaw sign convention — which direction of turn gives a positive Y+Z. Never formally checked; the invert flags paper over it.
  • Try it in an actual game over Shadow. The mouse is a real input device, so a streamed Windows game should accept it. Untested.
  • Check ch6/ch7 for a magnetometer. Values swung with orientation but were never isolated. A magnetometer would give absolute heading and kill yaw drift entirely.
  • Test on a second pair if you ever get the chance — the 15° mount offset may be unit-specific.

Two habits that saved a lot of time. Type commands rather than pasting — pasting injected stray characters and broke several scripts. And check the gravity magnitude before believing any sample: near 9.8 means the glasses were genuinely still.
